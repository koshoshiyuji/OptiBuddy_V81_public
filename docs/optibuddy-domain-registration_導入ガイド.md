# `optibuddy-domain-registration` スキル 導入ガイド

対象: このリポジトリ（OptiBuddy）をクローンし、Claude Code / Cowork経由で操作するユーザー。

---

## 1. このスキルの位置づけ（お読みください）

OptiBuddyはHuman-in-the-Loop（人間参加型）を設計哲学の中核に据えている。AIエージェントは
コード生成・診断・修正の実務を担うが、業務要件の確定・登録の可否・共有ファイルへの変更と
いった最終判断は、常に人間が行うことを前提に設計されている。

本スキルはその哲学を置き換えるものではない。**あくまでユーザー自身の作業を効率化するための
参考手順として提供しているものであり、OptiBuddy本体の仕様や正式な運用ルールではない。**
スキル内の「自律実行」は、初回のジョブ起動をユーザーが明示的に承認した後の指摘対応・登録可否
判断に限定され、かつ同一ジョブ内での自動対応回数に上限を設けている。この範囲を超えて処理が
続く場合や、判断に迷うケースでは、必ず人間（ユーザー）に差し戻す設計になっている。

したがって、このスキルを使うかどうか、どこまで自律的な処理を許容するかは、各ユーザーが自分の
運用方針に照らして判断してほしい。本ガイドおよびスキル本体は、その判断を助けるための参考
資料という位置づけである。

## 2. スキルが行うこと・行わないこと

行うこと:
- ヒアリングシートを受け取り、Flask APIを直接叩いてドメイン登録ジョブを起動する
- 生成コードへの指摘事項を実データ（生成コード・シナリオJSON・実ソルブ結果）に基づいて診断する
- 診断結果に基づき、上限付きで登録可否の3択（取りやめ／指摘を残して登録／続行＝AIエージェント対応）を選択する
- 実際のUI画面を開いて経過をスクリーンショットで報告する
- 登録成功後、既存ドメインと同じ方式（対話的な診断・実装・pytest検証）でソリューションチェック
  （`issue_rules.py`）の紐付けを試みる

行わないこと（人間の判断に委ねる部分）:
- 初回のジョブ起動（`/api/domain/run`、課金・不可逆）そのものの承認
- 共有ファイル（`solvers/base/issue_rules.py`等）へのアーキテクチャ変更の最終承認
- 自動対応の上限に達した後の続行判断
- ドメインの削除（別途ユーザー指示が必要）

## 3. 導入方法

このリポジトリには `.claude/skills/optibuddy-domain-registration/SKILL.md` が同梱されている。
Claude Code（CLI）またはこのリポジトリを開いたCoworkセッションでは、追加の登録作業なしに
プロジェクトスキルとして自動的に認識され、「OptiBuddyにドメイン登録して」等の依頼で呼び出される。

導入前に必ずSKILL.md全文を読み、「絶対に守ること」節（初回承認の要否、自律実行の上限）が
自分の運用方針と合っているか確認すること。上限回数や判断基準は、必要であれば自分の環境向けに
書き換えて構わない。

このリポジトリ以外の環境や、別アカウントでも使い回したい場合は、`.claude/skills/optibuddy-domain-registration/SKILL.md`
の内容をClaudeに渡し、「このスキルを自分のアカウントに登録したい」と伝えることでも登録できる
（Coworkの「スキル提案」フロー）。この場合はレビューカードで内容を確認してから保存する。

## 4. 使い方

依頼例:
- 「ヒアリングシート(添付)でOptiBuddyにドメイン登録して。プロジェクトルートは
  `~/work/OptiBuddy_V81_public` で」
- 「PopUpBoothSchedulerを登録して」（既にヒアリングシートを渡している場合）

必須の入力（揃っていなければClaudeから確認が入る）:
1. 作業対象のプロジェクトルート（このリポジトリを複数の場所にクローンしていたり、
   本番相当・検証用など複数環境を並行起動している場合、どこに対して作業するかは
   自明ではない）
2. 新規ドメイン名
3. ヒアリングシートの内容（ファイル添付推奨。テキスト直接貼り付けも可）

初回のジョブ起動時、Claudeから「実行してよいか」の確認が必ず入る。ここで承認すると、
以降の指摘対応・登録可否判断は（上限付きで）自動的に進む。

## 5. 制約・既知の注意点

- ヒアリングシートは必ずファイル添付で渡すことを推奨する。テキストをチャットに直接貼り付けた
  場合、Claude側での転記処理（JSON化＋ハッシュ検証、または画面への直接貼り付け）を経由するため、
  ごく稀に転記の齟齬が起こり得る（ファイル添付ならこの経路自体を回避できる）。
- 自律実行中の「続行（AIエージェントが対応）」選択は、同一ジョブにつき既定で最大2回まで。
  それでも解消しない指摘が残る場合は、必ず人間に差し戻される。
- 共有ファイル（`issue_rules.py`等）へのパッチが発生した場合は、他の既存ドメインへの
  巻き添え事故がないか確認する手順が組み込まれているが、最終的な安全確認はユーザー自身の
  実機確認に委ねられている。
- 初回のジョブ起動はユーザー自身の`ANTHROPIC_API_KEY`に課金が発生し、後から取り消せない。
  実行前に必ずClaudeから確認が入る設計だが、承認する際はこの点を踏まえること。
